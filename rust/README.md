# Rust, C, C++ и Go на общих массивах i32

Из корня репозитория запустите:

```sh
./rust/run.sh > reproduction.jsonl
```

Сценарий создает временный каталог, собирает исполняемые файлы и генерирует вход существующей программой cmd/gen. Для сборки нужны rustc, Go с модулями проекта, clang, clang++, заголовки C++ из third_party и Homebrew TBB по путям основного стенда. Для автономного прогона на другом arm64 Mac можно собрать Rust заранее:

```sh
rustc --edition 2021 -O rust/sort.rs -o rustsort
codesign -s - -f rustsort
```

После переноса бинарника на стенд передайте абсолютный путь:

```sh
GOPROXY=off RUSTSORT="$PWD/rustsort" ./rust/run.sh > reproduction.jsonl
```

[Опубликованный прогон](../results/rust-mini/raw.jsonl) выполнен последовательно на Mac mini M4 Pro, 12 ядер, 24 ГиБ, macOS 27.0.1 (26A434), powermode 0. Rust 1.98.0 (88d9e12ae, LLVM 22.1.8, aarch64-apple-darwin) собран на другом arm64 Mac. Контроли собраны на стенде: Apple Clang 21.0.0, SDK 27.0, libc++ 220106, Go 1.27.1.

Один миллион i32 хранится в little-endian. На каждом распределении все шесть реализаций сортируют данные из одного файла. Генератор Mulberry32 использует seed 42. Распределения: random, sorted, reverse, nearly (1000 случайных обменов после сортировки), few (значения 0-999). Прогрев занимает не менее 300 мс. Время последней пилотной сортировки определяет количество сортировок в серии с целевой длительностью 200 мс. Каждый процесс выполняет семь серий. Копирование исходного массива выполняется до старта таймера. Столбец ns_el содержит среднее время сортировки в серии, деленное на число элементов.

Все реализации проверяют порядок после каждой серии. Rust дополнительно сверяет результат с заранее отсортированной копией всего входа. Равные i32 неразличимы, поэтому этот тест измеряет время стабильной сортировки, но не проверяет сохранение порядка записей с одинаковыми ключами. В исходном C++ стенде std::sort и std::stable_sort получают один и тот же компаратор.

## Контроль обратного порядка

В основном reverse после сортировки случайных ключей есть 385 соседних равных пар. Первая пара занимает позиции 605 и 606 при нумерации с нуля. Для дополнительной проверки обе сортировки Rust получили строгую последовательность 1000000, 999999, ..., 1. Результаты находятся в [reverse-unique.jsonl](../results/rust-mini/reverse-unique.jsonl). Метка reverse обозначает порядок сортировки; этот файл содержит только контроль без повторов. Для воспроизведения в каталоге с собранным rustsort:

```sh
bun -e 'await Bun.write("strict.bin", new Int32Array(Array.from({length: 1000000}, (_, i) => 1000000 - i)))'
for method in sort sort_unstable; do
  ./rustsort "$method" i32 reverse strict.bin 1000000 7
done > reverse-unique.jsonl
```

Сразу после основных замеров в списке процессов corespotlightd занимал 175% CPU, Siri AI - 105%, photoanalysisd - 86.5%. Термопредупреждений не зарегистрировано. Контрольный повтор старых arm64-бинарников на сохраненном случайном массиве дал медианы 402.702 нс/элемент для qsort, 87.844 для std::sort и 314.261 для slices.Sort. Это близко к новым измерениям, но примерно в шесть раз выше архивных результатов. Причина расхождения не установлена. Абсолютные результаты из двух прогонов нельзя объединять.

[Полная повторная серия](../results/rust-mini/repeat.jsonl) и [повтор обратного контроля](../results/rust-mini/repeat-reverse-unique.jsonl) запущены, когда индексаторы выпали из списка самых активных процессов. Во время повторной серии mediaanalysisd занял 187% CPU, photolibraryd - 79%. Сохраненные и заново сгенерированные входы для пяти распределений побайтно совпали.

## Парный прогон Rust 1.98.0 и 1.100.0

[Основная серия 1.98.0](../results/rust-mini/rust-1.98.0-paired.jsonl) и [1.100.0](../results/rust-mini/rust-1.100.0-paired.jsonl) сравнивают версии на пяти исходных массивах по миллиону i32. Строгий обратный контроль сохранен отдельно для [1.98.0](../results/rust-mini/rust-1.98.0-paired-strict.jsonl) и [1.100.0](../results/rust-mini/rust-1.100.0-paired-strict.jsonl). Методика и число повторов совпадают с основным прогоном. Обе версии установлены официальным rustup. Сборка из каталога rust:

```sh
for v in 1.98.0 1.100.0; do
  rustup run "$v" rustc --edition 2021 -O sort.rs -o "sort-$v"
  codesign -f -s - "sort-$v"
done
```

Компиляторы для aarch64-apple-darwin: Rust 1.98.0 (88d9e12ae, LLVM 22.1.8) и 1.100.0 (0ef1bc386, LLVM 23.1.5). Все тайминги сняты на Mac mini с powermode 0. На каждом входе для sort_unstable первой шла 1.98.0, для sort - 1.100.0. Версии одного метода проверены подряд на тех же байтах.
